### 자산
**운영 › 자산**에 서버 · 도메인 · SSL 인증서 · 라이선스 · 클라우드 · 장비를 등록합니다.

- 항목: 구분 · 주소 · 사양 · 공급사 · 담당 · **만료일** · 갱신 주기 · 연결된 DB 서버 / Jenkins 서버
- 여러 프로젝트가 함께 쓰는 자산은 관리자가 **관리 › 자산 대장**에 공용 자산으로 등록하고 프로젝트에 연결합니다
- 목록 위 KPI: **만료됨 · 7일 이내 · 30일 이내**. 만료 30·7·1일 전 · 당일 · 다음 날에 담당자에게 메일로 알립니다
- 계정·비밀번호는 자산에 적지 말고 **접속정보(Vault)**에 등록하세요

### 스케줄러 (배치)
**운영 › 스케줄러**에 cron · Spring @Scheduled · Quartz · Windows 작업 스케줄러 · Jenkins · DB 잡을 한곳에 모읍니다.

- 일정을 입력하면 바로 **한국어 풀이**("평일 02:00", "09~18시 30분마다")와 **다음 실행 시각**을 보여 줍니다
- **24시간 타임라인**: 시간대별 실행 수, 가장 몰린 시간, 같은 서버에서 실행 시간이 겹치는 작업을 표시합니다
- **가져오기**
  - **서버에서 가져오기 (SSH)**: SSH 접속정보를 연결한 서버 자산을 고르면 서버에 접속해 계정 crontab · 시스템 crontab(`/etc/crontab`, `/etc/cron.d`)을 읽어 옵니다. 서버에서 없어진 작업은 지우지 않고 알려 줍니다
  - 서버에서 `crontab -l` 결과를 붙여넣기 (시스템 crontab 형식도 선택 가능)
  - DB 잡: DB 관리가 읽은 이벤트 · pg_cron · Oracle 스케줄러 · SQL Server 에이전트
  - Jenkins 배포 대상의 빌드 주기 · SCM 폴링
  - 같은 항목은 다시 가져와도 한 번만 들어갑니다
- 실행 계정 · 예상 소요 · 선후행 작업 · 실패 시 대응 · 관련 테이블을 적고 **배치 정의서** 엑셀로 받습니다

### 점검 · 장애
**운영 › 점검·장애**에서 장애 기록과 정기점검을 관리합니다.

#### 장애
1. 등급 · 발생 / 인지 / 복구 시각을 적으면 **중단 시간**이 자동 계산됩니다
2. 영향 범위 · 원인 · 조치 · 재발 방지 대책을 기록합니다
3. 후속 작업은 **일감 만들기**로 연결합니다

#### 정기점검
1. **점검표 양식**을 만들어 둡니다 (예: 월간 서버 점검 — 디스크, 백업, 로그, 인증서)
2. 점검할 때 양식을 골라 항목별로 정상 · 이상 · 해당 없음을 기록합니다

#### 월간 보고서
엑셀 한 파일에 요약 · 장애 · 정기점검 · 일감 처리 · 배포 이력 · DB 구조 변경 · 만료 예정 자산이 들어갑니다. 유지관리 월간 보고 자료로 씁니다.

### 인터페이스
**운영 › 인터페이스**에 외부·내부 시스템과의 연계를 정의합니다.

| 항목 | 예 |
|---|---|
| ID | IF-001 (자동) |
| 방향 · 상대 시스템 | 송신 / 수신 / 양방향 · 행정정보 공동이용 |
| 방식 | REST · SOAP · DB 링크 · SFTP · MQ · 배치 |
| 주기 | 실시간 또는 스케줄러의 작업 연결 |
| 데이터 · 관련 테이블 | 주고받는 항목, 읽고 쓰는 테이블 |
| 주소 · 담당 | 개발 / 운영 주소, 양쪽 담당자 |

- **구성도**: 인터페이스를 그림으로 보고 SVG · PNG · `.md` · draw.io 로 받습니다
- **인터페이스 정의서** 엑셀

### 접속정보 (Vault)
서버 · DB · 관리자 계정 같은 민감한 접속 정보는 **접속정보(Vault)**에 암호화해 보관합니다.

1. 프로젝트 **운영 › 접속정보** 또는 상단 **접속정보**에서 **새 접속정보**
2. 유형(서버·DB·웹 관리자 등) · 이름 · 주소 · 계정 · 비밀번호 · 메모를 적습니다. 파일(키 파일 등)도 암호화되어 저장됩니다
3. 목록에서 비밀번호는 가려져 있고 **복사** 버튼으로 바로 복사합니다
   - 줄 앞 **⋮⋮ 손잡이**를 끌어 순서를 바꿉니다(손잡이에서 위·아래 화살표도 됨, 편집 권한 필요). 제목 칸을 눌러 정렬하면 그 정렬로 보이고 손잡이는 숨겨집니다
4. 볼 수 있는 사람은 역할과 화이트리스트로 정합니다

> **보안 수칙** — 접속정보를 메신저 · 메일 · 위키 · 일감 본문에 적지 마세요. 인력이 철수하면 그 사람이 알던 계정의 비밀번호를 바꾸고 투입 인력의 **계정 회수일**을 기록합니다.

### SSH 터미널 (브라우저에서 서버 접속)
유형이 **SSH 서버**인 접속정보는 목록과 상세 화면에 **[▶ 접속]** · **[⚙ 접속 설정]** 버튼이 붙습니다. 프로그램 설치 없이 브라우저 새 탭에서 서버 터미널을 씁니다.

#### 접속 설정 (PM/PL)
1. 접속정보 줄의 **[⚙]** → 접속 설정 창
2. **구분**: 개발 / 운영 — 운영 서버는 접속할 때 사유와 프로젝트 식별자를 묻고, 화면을 항상 녹화합니다
3. **인증**: 이 접속정보의 비밀번호 / 개인키(같은 프로젝트의 "인증서·키 파일" 접속정보) / 접속할 때 직접 입력(저장 안 함)
4. **경유 서버**(최대 3대): PMS 서버에서 바로 닿지 않는 서버는 경유 서버를 거칩니다. 다른 "SSH 서버" 접속정보를 고르면 계정·비밀번호를 다시 적지 않아도 됩니다
5. **시작 명령**(선택): 예) `cd /app && sudo -iu tomcat`
6. **[접속 시험]**으로 단계별(경유 1 → 대상) 연결 결과를 확인하고 **[저장]**

> **서버 지문**: 처음 연결할 때 서버마다 지문을 기록하고, 이후 지문이 바뀌면 접속을 막습니다(서버를 바꿔치기한 경우 대비). 서버를 실제로 교체했다면 접속 설정에서 **지문 초기화**를 체크하고 저장하세요.

#### 접속
1. **[▶ 접속]** → 새 탭에 터미널이 열립니다 (운영 서버는 빨간 버튼 · 빨간 띠)
2. 위쪽 띠: 서버 이름 · 경로(경유 포함) · 접속 시간 · 글꼴 크기(A- A+) · **[끊기]**
3. 한글, 색상, `vi`·`top` 같은 전체 화면 프로그램, 창 크기 맞춤, 복사(드래그) · 붙여넣기를 지원합니다
4. 15분 동안 입력이 없으면 끊깁니다(1분 전에 알림). 한 번에 최대 4시간, 사람마다 동시에 5개까지
5. 끊긴 뒤 **[다시 연결]**로 같은 서버에 다시 접속합니다

#### 파일 올리기 · 받기
터미널 위쪽 **[파일]** 버튼 → 오른쪽(모바일은 전체 화면)에 파일 창이 열립니다. 같은 서버·같은 계정으로 연결됩니다.
- 폴더 이동(이름 누르기 · ↑ 상위 · 경로 직접 입력), **받기**(큰 로그도 바로 받기 시작), **올리기**(여러 개 · 끌어다 놓기 · 진행률, 한 번에 500MB), **새 폴더**, **이름 바꾸기**, **삭제**(폴더는 비어 있을 때만)
- 운영 서버는 올리기 · 새 폴더 · 이름 바꾸기 전에 한 번 더 확인하고, 삭제는 항상 확인합니다
- 파일 작업도 접속 기록에 남습니다 (접속 기록 › 재생 화면의 "파일 작업")
- 터미널 연결이 끊기면 파일 창도 쓸 수 없습니다

#### 권한 · 기록
| 권한 | 기본 역할 |
|---|---|
| 터미널 사용 (개발 서버) | PM/PL · 개발자 |
| 터미널 사용 (운영 서버) | **없음** — 필요한 사람에게만 관리자가 부여 |
| 접속 설정 편집 · 모든 접속 기록 보기 | PM/PL |

- 운영 서버 접속은 **2단계 인증을 켠 사용자**만 할 수 있습니다 (내 계정 › 2단계 인증 사용)
- 접속정보 목록 위 **[접속 기록]**: 누가 · 언제 · 어느 서버 · 사유 · 시간 · 종료 사유 · 접속 IP, 녹화 **[재생]**(1·2·4·8배속), 엑셀
- 녹화는 화면에 보이는 출력만 남깁니다 (화면에 나오지 않는 비밀번호 입력은 녹화되지 않음). 1년이 지나면 정리합니다
- PMS 서버에서 그 서버(또는 첫 경유 서버)로 SSH 접속이 열려 있어야 합니다. VPN 으로만 들어가는 서버는 고객사에 PMS 서버 IP 허용을 요청하세요

### 자산 자동 확인 (서버 정보 · 인증서)
- **서버 정보 수집**: 서버 자산 편집에서 **SSH 접속정보**를 고르면 목록에 **[정보 수집]** 버튼이 생깁니다. OS · CPU · 메모리 · 디스크 사용률 · 가동 일수를 읽어 목록에 보여 주고, 사양 칸이 비어 있으면 채웁니다
  - 디스크 사용률 80% 이상이면 빨간색으로 표시하고, 위쪽 **디스크 80% 이상** 칸을 누르면 그 서버만 봅니다
  - 그 접속정보에 터미널로 접속할 권한이 있어야 합니다. "접속할 때 직접 입력" 서버는 쓸 수 없습니다
- **인증서 확인**: 인증서 · 도메인 자산에 주소(`https://www.sample.go.kr` 또는 `www.sample.go.kr:8443`)가 있으면 **[인증서 확인]** — 인증서 이름 · 발급자 · 만료일을 읽습니다 (SSH 필요 없음)
  - **인증서** 유형 자산은 만료일이 인증서 만료일로 자동으로 바뀌어 만료 알림과 이어집니다. 도메인 유형은 등록 만료일을 그대로 둡니다
  - 주소와 인증서 이름이 다르면 빨간색으로 알려 줍니다
- 매일 자동으로 확인하려면 서버 관리자가 cron(`rake redmine:ops_asset:probe`)을 등록합니다

### 시스템 백업 (운영 서버 DB · 첨부파일)
**운영 › 시스템 백업**에서 프로젝트가 맡은 운영 서버의 DB 와 첨부파일 폴더를 PMS 서버에 날짜별로 보관합니다. 접속정보의 **SSH 서버**(접속 설정 · 경유 서버 그대로)로 접속합니다.

1. 오른쪽 위 **[DB 백업]** 또는 **[폴더 백업]**
2. **DB 백업**: SSH 서버 · DB 종류(MySQL·MariaDB / PostgreSQL / 직접 명령) · DB 주소(SSH 서버에서 본 주소, 같은 서버면 127.0.0.1) · 포트 · DB 이름 · **DB 계정**(접속정보에서 선택). 운영 서버에 `mysqldump`/`pg_dump` 가 있어야 합니다
3. **폴더 백업**: 백업할 폴더(절대 경로, 한 줄에 하나) · 제외(`*.tmp`, `cache/` 등). 두 번째부터는 **바뀐 파일만** 받습니다
4. **일정**: 수동 / 매일 / 매주(요일) + 시각 — 운영 부하가 적은 새벽 권장. **보관**: 최근 몇 번을 남길지
5. 작업 화면의 **[지금 백업]** → 실행 기록에 완료 · 받은 양 · 파일 수 · 걸린 시간이 남습니다. 실패하면 이유(예: 비밀번호 틀림)가 보입니다

- DB 백업은 실행 기록의 **[덤프 받기]**(`.sql.gz`)로 받을 수 있습니다. 덤프에는 실데이터가 들어 있으니 받은 파일은 조심해서 다루세요
- **복원은 자동으로 하지 않습니다.** 작업 화면의 **복원 방법** 명령을 참고해 담당자가 직접 복원하세요 (복원 전에 현재 DB 를 먼저 백업)
- 권한: **시스템 백업 보기·덤프 받기** / **시스템 백업 관리·실행** (기본 PM/PL). 실행하려면 그 SSH 서버에 터미널로 접속할 권한도 있어야 합니다
- 일정 실행은 서버 관리자가 cron(`rake redmine:sys_backup:run`, 매시)을 등록해야 동작합니다

### 백업 (관리자)
- PMS 는 매일 DB · 첨부파일 · 키 파일을 서버 안에 날짜별로 백업하고 14일 동안 보관합니다
- **관리 › 백업**에서 최근 백업 상태 확인과 **[지금 백업]**을 할 수 있습니다. 복원은 서버 관리자가 복원 스크립트로 합니다
