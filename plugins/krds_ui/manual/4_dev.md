### 저장소 — 커밋을 일감에 연결
커밋 메시지에 **`refs #일감번호`** 를 함께 적으면 그 커밋이 해당 일감에 자동으로 연결됩니다. 일감 상세 화면의 **연관된 리비전** 에 커밋이 표시되고, 클릭하면 변경된 소스(diff)를 바로 볼 수 있습니다. 작업이 끝났다면 `refs` 대신 **`fixes`** 를 쓰면 일감이 **해결** 상태로 바뀌고, **`@시간`** 을 붙이면 작업 시간이 소요시간에 기록됩니다.

```
회원사 저장 시 사업자번호 중복 체크 수정 refs #12
로그인 세션 만료 처리 개선 refs #12, #15
첨부파일 업로드 오류 수정 fixes #15 @1h30m
```

| 키워드 | 동작 |
|---|---|
| `refs` `references` `IssueID` | 일감에 커밋만 연결 (상태 변화 없음) |
| `fixes` `resolves` | 연결 + 일감 상태 **해결**, 진척도 100% |
| `closes` | 연결 + 일감 상태 **완료**, 진척도 100% |
| `@2h` `@30m` `@1h30m` | 일감 번호 바로 뒤에 붙이면 **소요시간**(작업분류: 개발)으로 기록 |

- **여러 일감**: 쉼표나 공백으로 이어 적습니다 (예: `refs #12, #15`)
- **같은 프로젝트의 일감만** 연결됩니다. 일감 번호는 일감 제목 앞의 `#번호` 를 확인하세요
- **계정 연결**: SVN 계정과 Redmine 아이디가 같아야 커밋한 사람이 표시되고, 상태 변경·소요시간이 본인 이름으로 기록됩니다
- **반영 시점**: 새 커밋은 **5분마다** 자동으로 가져옵니다. 급하면 프로젝트의 **저장소** 탭을 열면 바로 반영됩니다
- 이미 **완료·거절** 된 일감은 `fixes` 로 상태가 바뀌지 않습니다
- 저장소 화면에서 리비전·변경 파일·diff 를 보고, **소스코드 다운로드**(zip)로 특정 시점 소스를 받을 수 있습니다

### 프로그램 목록 — 기능 단위
**개발 › 프로그램 목록**은 서버 처리가 있는 기능 하나를 프로그램 하나로 관리합니다. 메뉴 구조도(화면 단위)를 먼저 완성한 뒤 만듭니다.

#### 넣는 기능과 넣지 않는 것
**넣는 기능** — 서버 처리가 있는 버튼·동작: 조회·검색, 등록, 수정, 삭제, 승인·반려 같은 상태 변경, 엑셀·파일 다운로드, 업로드, 출력. 그 밖에 팝업 화면, 배치, 외부 연계 API, 공통 모듈도 프로그램입니다.

**넣지 않는 것** — 화면 안에서만 동작하는 버튼: 닫기, 초기화, 탭 전환, 접기·펼치기, 화면에서만 하는 입력값 검사

#### 프로그램 ID
 화면 ID 뒤에 처리 구분 접미어를 붙입니다.

| 접미어 | 처리 구분 | 예 |
|---|---|---|
| `-S` | 조회 (목록·상세·검색) | `PT-BBS-001-S` 공지사항 : 목록 조회 |
| `-I` | 등록 | `PT-BBS-003-I` 공지사항 등록·수정 : 등록 |
| `-U` | 수정 | `PT-BBS-003-U` |
| `-D` | 삭제 | `PT-BBS-003-D` |
| `-X` | 다운로드 (엑셀·파일) | `PT-BBS-001-X` 공지사항 : 엑셀 다운로드 |
| `-F` | 업로드 | `AD-MBR-001-F` 회원 일괄 등록 |
| `-P` | 출력 | `AD-STA-001-P` |
| `-A` | 승인·반려 등 상태 변경 | `AD-APR-001-A` |
| `-E` | 기타 | |

- 같은 처리가 둘 이상이면 번호를 붙입니다 (예: `-S1` 목록 조회, `-S2` 건수 조회)
- 화면이 없는 프로그램: 배치 `BAT-업무-번호`, 연계 API `API-업무-번호`, 공통 `CMN-업무-번호` (유형도 배치·API·공통으로)

#### 만드는 방법
1. 메뉴 구조도를 먼저 완성합니다 (화면 ID · 화면 유형까지)
2. 프로그램 목록의 **메뉴 구조도에서 만들기 › [기능 단위]** — 화면 유형별 기본 기능을 자동으로 만듭니다: 목록 → 조회 · 엑셀 다운로드, 상세 → 조회, 등록·수정 → 등록 · 수정 · 삭제, 팝업·탭 → 조회
3. 필요 없는 줄은 지우고(예: 엑셀 다운로드가 없는 목록), 빠진 기능(승인·업로드 등)은 **[새 프로그램]** 으로 추가합니다. 다시 눌러도 이미 있는 ID 는 건너뛰므로 화면을 추가한 뒤 또 눌러도 됩니다
4. 프로그램마다 **처리 구분 · 소스 경로 · 개발자 · 계획일** 을 채웁니다. 소스 경로는 **[소스 경로 추천]** 으로 커밋에서 찾을 수 있습니다

- **[화면 단위]** 는 화면 1개 = 프로그램 1개로 만듭니다 (작은 프로젝트·초기 산정용). 나중에 [기능 단위] 로 바꾸면 화면 단위 프로그램은 그대로 남으니 정리해 주세요
- **진척 상태**: 미착수 → 개발 중 → 개발 완료 → 단위테스트 완료. 목록은 화면별로 묶여 화면마다 프로그램 수 · 완료 수를 보여 줍니다
- **단위테스트**: 테스트 케이스 등록 화면에서 **프로그램** 을 고르면 케이스 · 테스트 결과서에 프로그램 ID 가 표시되고, 프로그램 상세에서 최근 결과를 볼 수 있습니다

### DB 관리
**개발 › DB**에서 개발·운영 DB 의 구조를 조회하고 산출물을 만듭니다. DB 연결은 관리자가 **관리 › DB 서버**에 등록하고, PM/PL 이 **설정 › DB** 에서 프로젝트에 연결합니다. (조회 전용 계정 권장)

- **종류 탭**: 테이블 · 뷰 · 함수 · 프로시저 · 트리거 · DB 잡 · 시퀀스 (DB 종류에 따라 다름). 테이블은 컬럼·키·인덱스·설명·용어사전 대조
- **ERD**: 테이블을 골라 그림으로 보고 `.md` · `.mmd` · **draw.io** · SVG · PNG 로 받습니다 (점선은 FK 없이 이름으로 추정한 관계)
- **테이블 정의서**: 엑셀 (테이블 목록 · 컬럼 정의 · 인덱스 · 객체)
- **비교**: 개발 DB 와 운영 DB 의 차이 (한쪽에만 있는 테이블·컬럼 차이·객체 정의 차이)
- **이관** (MariaDB·MySQL · PostgreSQL · MS SQL Server · Oracle — 같은 종류끼리): 비교 옆 **[이관]** 탭에서 **원본 → 대상**(개발 → 운영, 운영 → 개발, [방향 바꾸기])을 고르고 테이블마다 방식을 고릅니다
  - **구조만**: 없는 테이블은 만들고, 있는 테이블은 칼럼 추가·변경, 인덱스·외래키·설명을 원본에 맞춤 (데이터 그대로)
  - **구조+데이터 (전체 교체)**: 대상 데이터를 모두 지우고 원본으로 채움 / **(추가·갱신)**: 기본키·유일키가 같으면 고치고 없으면 추가 / **(없는 것만)**: 없는 행만 추가
  - [차이 있는 테이블만] · [보이는 테이블 모두] 로 한꺼번에 고르고 **[미리보기]** → 실행할 SQL·알림 확인, **[SQL 내려받기]**
  - **[이관 실행]**: 먼저 바뀔 대상 테이블을 PMS 서버에 백업하고 테이블마다 차례로 진행합니다. 결과 화면에서 옮긴 행 수·대상 행 수·백업 받기
  - 대상에만 있는 테이블·칼럼·인덱스는 **지우지 않습니다**. 기본키가 다르면 바꾸지 않고 알려 줍니다
  - **뷰·함수·프로시저**(DB 에 따라 구체화 뷰·패키지도): 표 아래 목록에서 고르면 대상에 만들거나 원본 정의로 바꿉니다. 테이블 다음에 함수·패키지 → 뷰 → 프로시저 순서로, 다른 개체에 기대 실패하면 최대 3번 다시 시도합니다. 바꾸기 전 대상의 정의를 백업합니다
    - 상태 '비교 불가': 조회 계정이 정의를 볼 수 없어 비교하지 못한 경우 (MariaDB 는 정의자이거나 mysql.proc 조회 권한이 있어야 함수·프로시저 본문이 보임)
    - MariaDB 는 DEFINER 를 빼고 만들어 이관용 계정이 정의자가 됩니다. Oracle 은 컴파일 오류가 있으면 실패로 표시합니다
  - 운영 DB 가 대상이면 사유와 프로젝트 식별자를 입력해야 실행됩니다. 권한은 **DB 이관 (대상: 개발 DB)** / **DB 이관 (대상: 운영 DB)** 따로
  - 대상 DB 에 쓰려면 관리 › DB 서버에 **이관용 계정**(쓰기 권한)을 등록하세요. 비우면 조회용 계정으로 시도합니다
  - 외래키로 연결된 테이블은 참조되는 테이블부터 차례로 옮깁니다. PostgreSQL 은 이관용 계정이 슈퍼유저가 아니면 외래키 검사를 끌 수 없어, 다른 테이블이 참조하는 행을 지우는 전체 교체는 실패할 수 있습니다(그 테이블은 되돌림)
  - 되돌리기: 결과 화면의 백업 파일(.sql.gz)을 대상 DB 의 클라이언트(mysql · psql · sqlcmd · SQLcl/SQL*Plus)로 실행하면 그 테이블이 이관 전으로 돌아갑니다. 이 테이블을 참조하던 외래키도 다시 만듭니다
- **변경 이력**: [지금 구조 저장] 또는 자동 저장 — 구조가 바뀐 경우만 저장, 저장본끼리 비교
- **SQL 조회**: 조회 문장 하나만 실행(변경 문장 거부, 읽기 전용, 시간·건수 제한), CSV 받기, 실행 기록. 운영 DB 조회 권한은 따로 있습니다
- **용어 점검** · **개인정보 컬럼**(분류·암호화 여부·경고) · **공통코드 정의서**

### 테스트
**개발 › 테스트**에서 테스트 케이스를 만들고 회차별로 결과를 기록합니다.

1. **케이스 등록**: 종류(단위·통합·인수) · 메뉴 · 요구사항(여러 개) · **프로그램** · 사전조건 · 절차 · 기대결과. 단위테스트는 프로그램 단위로 만듭니다
2. **회차 만들기**: 예) "1차 통합테스트" — 종류가 맞는 사용 중 케이스가 대상이 됩니다. 나중에 추가한 케이스는 **[새 케이스 대상에 추가]**
3. **결과 입력**: 한 화면에서 미수행 · 합격 · 불합격 · 보류 · 제외와 비고를 고치고 한 번에 저장 (바뀐 줄 표시)
4. **결함**: 불합격 줄의 **[결함 일감 만들기]** → "결함" 유형 일감이 절차·기대결과·실제 결과와 함께 만들어지고 메뉴에 연결됩니다
5. **재테스트**: 결함 일감이 완료되면 그 케이스에 재테스트 표시가 나옵니다
6. **엑셀**: 테스트 시나리오(가져오기·내보내기), 회차별 테스트 결과서

- **메뉴별 현황**에서 테스트 케이스가 없는 화면을 찾습니다
- 프로그램 목록의 **상태 제안**은 연결 테스트가 모두 합격이면 "단위테스트 완료"를 제안합니다

### 보안약점 진단
**개발 › 보안약점**에서 진단 회차별로 결과를 관리합니다.

1. 회차 등록: 진단 도구 · 진단일 · 대상 리비전 · 진단자
2. 도구 결과(엑셀·CSV)를 가져옵니다 — 머리줄 이름으로 유형·위험도·파일·라인·설명을 찾습니다
3. 항목마다 **조치**(조치자·조치일) 또는 **예외**(사유 필수)를 기록합니다. 여러 항목을 골라 한 번에 바꿀 수 있습니다
4. 재진단 결과를 표시하고, 결과·조치 내역을 엑셀로 받습니다

### Jenkins 배포
프로젝트의 **배포** 탭에서 Jenkins 배포 작업을 실행하고 결과·이력을 확인할 수 있습니다. Jenkins 에는 플러그인 설치가 필요 없고, 배포 전용 계정의 **API 토큰**만 있으면 됩니다.

**1. Jenkins — 배포 계정과 API 토큰 (Jenkins 관리자)**
- **Jenkins 관리 → Users → Create User** 로 배포 전용 계정을 만듭니다 (예: `redmine-deploy`)
- 그 계정으로 로그인 → 오른쪽 위 **사용자 이름 → Security** (주소 `/me/security/`) → **API Token → Add new Token → Generate**
- 토큰은 한 번만 보이니 바로 복사해 아래 2번에 입력합니다. 메신저·메일로 공유하지 마세요

**2. Redmine — Jenkins 서버 등록 (Redmine 관리자)**
- **관리 → Jenkins 서버 → 새 Jenkins 서버** 에 주소(`http://<Jenkins 주소>:<포트>`), 계정, API 토큰 입력 → 저장 → **연결 시험**
- "연결됨 — Jenkins 버전, 계정" 이 나오면 성공입니다. 토큰은 암호화되어 저장되고 다시 표시되지 않습니다

**3. Redmine — 권한 지정 (Redmine 관리자)**
- **관리 → 역할 및 권한** 의 "배포" 항목: 배포 이력 보기 / 배포 실행 / 운영 배포 실행 / 배포 설정 관리

**4. 프로젝트 — 배포 환경 등록 (프로젝트 관리자)**
- **설정 → 프로젝트 → 모듈** 에서 **배포** 를 켭니다
- **설정 → 배포 → 새 배포 환경**

| 항목 | 입력 |
|---|---|
| Jenkins 작업 경로 | Jenkins 에서 작업을 열었을 때 주소의 `/job/` 뒤 이름 (폴더 안이면 `폴더/작업`) |
| 운영 환경 | 운영 서버에 배포하는 작업이면 체크 — 실행할 때 프로젝트 식별자를 입력해야 합니다 |
| 기본 매개변수 | 확인창에 미리 채울 값 — 아래 **기본 매개변수 작성법** 참고 |

**기본 매개변수 작성법**

배포 실행 확인창은 Jenkins 작업에 정의된 매개변수를 읽어 와 입력칸으로 보여 줍니다. **기본 매개변수**는 그 입력칸에 처음 채워 둘 값이며, 비워 두면 Jenkins 작업의 기본값이 쓰입니다. 실행할 때 확인창에서 바꿀 수 있습니다.

- 한 줄에 하나씩 `이름=값` 으로 씁니다. `=` 앞뒤에 공백을 넣지 않습니다
- 이름은 Jenkinsfile 의 `name` 과 **대소문자까지 같아야** 합니다. Jenkins 에 없는 이름은 전달되지 않습니다

| Jenkins 매개변수 | 확인창 | 기본 매개변수 예 |
|---|---|---|
| `booleanParam` (체크박스) | 체크박스 | `DEPLOY_PROD=true` (체크) / `DEPLOY_PROD=false` (해제) — 소문자 |
| `choice` (선택 목록) | 선택 목록 | `TARGET=was2` — Jenkins 선택지 중 하나만 가능 |
| `string` · `text` (문자열) | 입력칸 | `BRANCH=develop` |
| `password` (비밀번호) | 표시 안 함 | 지원하지 않음 — Jenkins Credentials 를 쓰세요 |

- `REDMINE_USER` · `REDMINE_RUN_ID` 는 Redmine 이 자동으로 채우므로 적지 않습니다
- 예) 개발서버 — 비워 둠(매개변수 없는 작업) / 운영서버 — `DEPLOY_PROD=true` (빌드만 할 때는 확인창에서 체크 해제)

**5. Jenkinsfile — 매개변수 추가 (권장)**

`pipeline {` 안에 아래를 넣으면 Redmine 이 실행자와 기록 번호를 자동으로 채워 Jenkins 빌드와 정확히 연결됩니다. 수정한 Jenkinsfile 로 한 번 실행된 뒤부터 적용됩니다.

```groovy
parameters {
    string(name: 'REDMINE_RUN_ID', defaultValue: '', trim: true, description: 'Redmine 배포 기록 번호 (자동 입력)')
    string(name: 'REDMINE_USER',   defaultValue: '', trim: true, description: 'Redmine 에서 실행한 사용자 (자동 입력)')
}
```

**6. 배포 실행**
- 프로젝트 **배포** 탭 → 환경 카드의 **배포 실행** → 확인창에서 매개변수(체크박스·선택 목록·입력칸)를 확인·변경 → 실행
- 진행 중에는 10초마다 상태가 갱신되고, 같은 환경은 끝날 때까지 다시 실행할 수 없습니다
- 배포 이력에는 Redmine 에서 실행한 빌드와 Jenkins 에서 직접 실행한 빌드가 함께 표시되며, 빌드 번호를 누르면 Jenkins 로그를 볼 수 있습니다
