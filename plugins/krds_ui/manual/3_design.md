### 요구사항
**설계 › 요구사항**에 사업의 요구사항을 공공 표준 분류로 등록합니다. ID 를 비우면 분류 접두어로 자동 번호가 붙습니다 (예: SFR-001).

| 접두어 | 분류 | 접두어 | 분류 |
|---|---|---|---|
| SFR | 기능 | SER | 보안 |
| PER | 성능 | QUR | 품질 |
| SIR | 인터페이스 | COR | 제약사항 |
| DAR | 데이터 | PMR | 프로젝트 관리 |
| TER | 테스트 | PSR | 프로젝트 지원 |

- **상태**: 접수 → 확정 → (변경) → 삭제. 확정·변경된 요구사항만 준공 체크리스트에서 "확정"으로 셉니다
- **메뉴 연결**: 요구사항을 구현하는 메뉴(화면)를 여러 개 고릅니다 — 하위 메뉴도 함께 따라옵니다
- **일감 연결**: 일감 번호로 연결합니다. 일감 상세에도 연결된 요구사항이 보입니다
- 목록 위 KPI(전체·확정·메뉴 미연결·테스트 없음·불합격 있음·테스트 통과)를 누르면 해당 요구사항만 걸러 봅니다
- **변경 이력**: 요구사항 상세에서 칸별로 이전 → 이후 값과 메뉴·일감 연결 변경을 볼 수 있습니다
- **엑셀**: [내보내기]로 요구사항 정의서·추적표, [가져오기]는 머리줄 이름(요구사항 ID·분류·요구사항명·상세·출처·중요도·상태·상위 ID·메뉴)으로 칸을 찾습니다. ID 가 같으면 값만 갱신합니다

### 요구사항 추적표
요구사항 화면의 **[추적표]** 탭에서 요구사항마다 끝까지 따라갑니다.

**요구사항 → 메뉴 → 화면 캡처 → 프로그램 → 일감 → 테스트 케이스(최근 결과) → 결함 → 위험**

- **화면 캡처**: 요구사항 메뉴(하위 포함) 중 화면인 것과 캡처된 수 (예: 2/3 캡처)
- **위험** 표시: 메뉴 미연결 · 프로그램 없음 · 테스트 없음 · 불합격 — 감리 전에 위험 표시가 없도록 정리하세요
- 엑셀 내보내기의 "요구사항 추적표" 시트를 감리·검수 자료로 그대로 씁니다

### 변경요청
요구사항 화면의 **[변경요청]** 탭에서 관리합니다. 번호는 CR-001 부터 자동입니다.

1. **접수**: 요청자·요청 사유·변경 내용을 적습니다
2. **영향 분석**: 영향 받는 요구사항·메뉴·인터페이스·테이블을 고르고 추가 공수·일정 영향을 적습니다
3. **결정**: 승인 권한(PM/PL)이 있는 사람이 승인 또는 반려합니다 (사유 필수)
4. **반영**: 승인된 변경요청에서 **[반영 일감 만들기]** — 일감이 연결되어 진행 상황을 추적하고, 끝나면 **반영 완료**로 바꿉니다

> 승인으로 일정이 바뀌면 **일정 기준선**을 새로 저장해 두면 변경 전후를 비교할 수 있습니다.

### 메뉴 구조도
**설계 › 메뉴 구조도**는 개발할 시스템의 화면을 정리하는 엑셀형 표입니다. 메뉴 구조도와 프로그램 목록은 **단위**로 구분합니다 — 메뉴 구조도는 **화면** 단위, 프로그램 목록은 **기능(서버 처리)** 단위입니다.

| | 메뉴 구조도 (설계 › 메뉴 구조도) | 프로그램 목록 (개발 › 프로그램 목록) |
|---|---|---|
| 단위 | 화면 — 사용자가 보게 되는 화면 하나 | 기능 — 서버 처리가 있는 버튼·동작 하나 |
| 질문 | "어떤 화면이 있나?" | "무엇을 만들어야 하나?" |
| 예 | 공지사항 목록 / 상세 / 등록·수정 | 공지사항 목록 조회, 엑셀 다운로드, 상세 조회, 등록, 수정, 삭제 |
| 연결 | 요구사항 · 일감 · 시스템 권한 | 소스 경로 · 개발자 · 진척 · 단위테스트 |

**표 다루기**
- 칸을 눌러 바로 고치고, **Tab / Shift+Tab** 으로 들여쓰기·내어쓰기(뎁스)를 합니다. 행 왼쪽 손잡이를 끌어 순서를 옮깁니다
- 행 ⋯ 메뉴에서 연결된 일감 보기 · 새 일감 · 삭제 · 다른 사이트로 옮기기를 합니다. 메뉴를 지워도 연결된 일감은 남습니다
- **[칼럼 관리]**로 프로젝트에 필요한 칸(예: 담당 부서)을 더할 수 있습니다
- 표 위 오른쪽 **[모두 펼치기] [모두 접기] [화면 유형]** — **[화면 유형]** 창에서 이 프로젝트의 화면 유형을 추가 · 삭제 · 이름 변경하고, 유형마다 **메뉴에 보임**(메뉴 노출 기본값)을 정합니다. 쓰고 있는 유형을 지우면 그 화면들의 유형은 비워집니다
- 여러 메뉴를 고르고 **[고른 메뉴로 일감 만들기]** — 메뉴마다 일감이 만들어지고 연결됩니다 (이미 연결된 메뉴는 건너뛰기 선택)
- **[구조도]** 탭은 Mermaid 그림(SVG·PNG), **[현황]** 탭은 메뉴별 일감·테스트 현황입니다
- 엑셀 가져오기·내보내기를 지원합니다 (첫 칸 **사이트**)

#### 작성 규칙 — 화면 단위
**사이트 나누기**: 사용자 페이지 · 관리자 페이지처럼 시스템이 둘 이상이면 표 위 **[사이트 나누기]** 로 사이트를 먼저 만듭니다. 처음 만든 사이트에 기존 메뉴가 모두 들어가고, 다른 사이트로는 행 ⋯ 메뉴의 **[○○(으)로 옮기기]** 로 옮깁니다. 엑셀은 첫 칸에 **사이트** 를 적습니다.

**넣는 화면** — 메뉴에서 바로 들어가는 화면만이 아니라 **사용자가 보게 되는 화면은 모두** 넣습니다.

| 구분 | 예 | 넣는 위치 | 화면 유형 | 메뉴 노출 |
|---|---|---|---|---|
| 목록 | 공지사항 목록 | 말단 메뉴 (보통 메뉴 = 목록) | 목록 | Y |
| 상세 | 공지사항 상세 | 목록의 하위 행 | 상세 | N |
| 등록·수정 | 공지사항 등록·수정 | 목록의 하위 행 (등록·수정 화면이 다르면 두 줄) | 등록·수정 | N |
| 팝업 | 우편번호 찾기, 회원 선택 | 팝업을 여는 화면의 하위 행 | 팝업 | N |
| 탭 | 회원 상세의 [기본정보][이력] (화면이 따로일 때) | 그 화면의 하위 행 | 탭 | N |
| 단계 화면 | 회원가입 약관 동의 → 본인인증 → 정보 입력 → 완료 | 단계마다 한 줄 | 등록·수정 등 | 첫 단계만 Y |
| 공통 화면 | 메인, 로그인, 통합검색 결과, 이용약관, 개인정보처리방침, 사이트맵, 오류(404·500) | 1뎁스 **공통** 을 따로 두고 그 아래 | 목록·상세 등 | 메뉴에 있으면 Y |

**넣지 않는 것**: 같은 화면 안의 버튼·동작(저장, 삭제, 엑셀 다운로드 → 프로그램 목록), 화면이 바뀌지 않는 알림·확인창, 화면 안에서만 바뀌는 검색 조건·정렬

**칸 작성**
- **뎁스**: 실제 사이트 메뉴판 그대로 1뎁스부터 적고, 상세·등록·팝업은 그 화면의 하위 행으로 둡니다 (Tab 들여쓰기)
- **화면 ID**: `사이트-업무-번호` 를 권장합니다. 예) 사용자 `PT-BBS-001`(목록) · `PT-BBS-002`(상세) · `PT-BBS-003`(등록·수정), 관리자 `AD-MBR-001`. 같은 업무의 상세·등록은 목록 다음 번호로 이어 붙이고, 한 번 정한 ID 는 바꾸지 않습니다 (프로그램 ID·테스트·산출물이 이 ID 를 씁니다)
- **메뉴 노출**: 실제 메뉴에 보이면 **Y**, 메뉴에는 없고 화면만 있으면 **N**. 화면 유형을 상세·등록·수정·팝업·탭으로 고르면 자동으로 N 이 되고, 바꿀 수 있습니다. 구조도의 **[메뉴만 보기]** 는 Y 만 그려 사이트맵·메뉴판으로 쓸 수 있습니다
- **URL**: 화면 주소 (`/bbs/notice/list.do` 처럼 사이트 기본 주소 뒤 경로)
- **채널**: 공통 · PC · 모바일 / **사용**: 개발하지 않거나 폐기한 화면은 N (지우지 말고 N 으로 남기면 이력이 유지됩니다)
- **시스템 권한**: 화면마다 권한 등급별 조회(R) · 등록·수정(CRU) · 전체(CRUD) — 관리자 페이지 전용 등급은 적용 사이트를 지정합니다

```
[사용자 페이지]
알림마당
└ 공지사항            PT-BBS-001  목록       메뉴 노출 Y
   ├ 공지사항 상세     PT-BBS-002  상세       N
   └ 공지사항 등록·수정 PT-BBS-003  등록·수정  N
공통
├ 메인                PT-CMN-001  목록       Y
└ 로그인              PT-CMN-002  등록·수정  Y
```

### 시스템 권한
**설계 › 시스템 권한**은 개발할 시스템의 권한 등급(예: 일반회원·운영자·관리자)을 정의하고, 메뉴 × 권한 **매트릭스**로 화면마다 조회(R) · 등록·수정(CRU) · 전체(CRUD)를 지정합니다. 관리자 페이지 전용 등급은 적용 사이트를 고릅니다. 결과는 엑셀(권한 정의서)로 받습니다.

### 화면 캡처 · 화면 설계서
메뉴 구조도의 **[화면 캡처]** 탭에서 서버가 운영(또는 개발) 사이트에 로그인해 화면을 자동으로 캡처합니다. 캡처는 화면 설계서·감리 자료로 그대로 씁니다.

#### 처음 설정 (PM/PL)
1. **[캡처 설정]** — 사이트별로 기본 주소(예: `https://www.sample.go.kr`)를 적습니다
2. 로그인이 필요하면 로그인 주소 · 아이디 · 비밀번호를 적습니다. 비밀번호는 암호화되어 다시 표시되지 않습니다
3. **로그아웃 주소**(예: `/member/logout.do`)를 적으면 로그인 후 화면에 그 주소로 가는 링크·폼·스크립트가 있을 때 로그인 성공으로 봅니다. 버튼이 아닌 글자 링크도 인정합니다
4. 입력칸·로그인 버튼 선택자는 보통 비워 두면 자동으로 찾습니다. 못 찾으면 CSS 선택자(예: `#loginId`)를 적습니다
5. **[로그인 시험]**으로 로그인 결과 화면을 확인합니다
6. 너비(기본 1440)·모바일(390px) 함께 캡처·화면마다 기다림·자동 캡처(매일·매주 월)를 정합니다

> 캡처에는 화면 내용이 그대로 담깁니다. **조회 권한만 있는 테스트 계정·테스트 데이터**로 설정하세요.

#### 캡처와 결과
- **[지금 캡처]** — 백그라운드로 실행되고 화면이 5초마다 진행 상황을 보여 줍니다
- 메뉴 구조도의 **URL** 이 `/` 로 시작하면 기본 주소의 호스트 뒤에 붙여 엽니다. URL 이 없는 화면은 건너뜁니다
- 화면 카드: 최신 미리보기 · **바뀜**(지난 캡처와 다름) · 오류 · 캡처 없음 · URL 없음
- 화면을 누르면 이력, 두 시점 나란히 비교, 원본·모바일·내려받기
- **[화면 설계서(PPT)]** — 표지 · 개정 이력 · 화면 목록 · 화면마다 1장(캡처 + 화면 ID·메뉴 경로·URL·접근 권한·요구사항·프로그램 + 화면 설명 빈칸)의 PowerPoint 를 만듭니다. 산출물 **D-03 화면 설계서**에서도 받을 수 있습니다

### 웹 접근성 자동 점검
캡처할 때 PC 화면마다 웹 접근성을 자동으로 점검하고, 위반을 **한국형 웹 콘텐츠 접근성 지침(KWCAG 2.2)** 항목으로 묶어 보여 줍니다. (캡처 설정의 "웹 접근성 점검"으로 끄고 켭니다)

- 화면 카드에 **접근성 n**(위반 규칙 수) 또는 **접근성 통과**, KPI **접근성 위반**을 누르면 위반 화면만 봅니다
- 화면 상세의 위반 표: 심각도(치명·심각·보통·경미) · KWCAG 항목 · 내용 · 요소 수 · 예시 위치(CSS 선택자)
- **[결함 일감 만들기]** — 그 화면의 위반을 결함 일감 하나로 등록하고 메뉴와 연결합니다
- **[웹 접근성 점검표]** 엑셀 — KWCAG 항목별 요약 · 화면별 위반 · 화면별 건수 · 안내

| 자주 나오는 위반 | KWCAG 항목 | 고치는 방법 |
|---|---|---|
| 이미지 대체 텍스트 없음 | 5.1.1 | `<img alt="설명">`, 꾸밈 이미지는 `alt=""` |
| 명도 대비 부족 | 5.4.3 | 글자와 배경 대비 4.5:1 이상 (큰 글자 3:1) |
| 입력칸 레이블 없음 | 7.3.2 | `<label for="id">` 또는 `aria-label` |
| 링크·버튼 이름 없음 | 6.4.3 · 8.2.1 | 아이콘만 있으면 `aria-label` 또는 숨김 글자 |
| 페이지 언어 없음 | 7.1.1 | `<html lang="ko">` |
| 제목 없음 | 6.4.2 | `<title>` · 화면 제목 `<h1>`~ |

> 자동 점검은 KWCAG 33개 항목 중 일부만 확인합니다. 키보드만으로 사용 · 초점 이동과 표시 · 자막 · 깜빡임 · 오류 정정 · 접근 가능한 인증은 사람이 직접 확인해야 합니다.

### 용어사전
**설계 › 용어사전**에 프로젝트 용어를 등록합니다. 모든 프로젝트가 함께 쓰는 용어는 관리자가 **관리 › 공통 용어사전**에 등록하며 `공통` 배지로 함께 보입니다.

- 항목: 용어 · 영문명 · 약어 · 분류 · 데이터 타입 · 길이 · 정의 · 비고
- **가져오기**: 머리줄 `용어,영문명,약어,분류,데이터타입,길이,정의,비고` 의 CSV (엑셀 "CSV UTF-8" 저장). **행정안전부 공공데이터 공통표준용어 CSV** 는 그대로 올리면 됩니다
- 본문에 `{{term(고객번호)}}` 라고 쓰면 `고객번호 (CUST_NO)` 로 표시되고 정의가 툴팁으로 나옵니다
- DB 화면의 **[용어 점검]**에서 컬럼명을 용어사전 약어와 대조합니다
