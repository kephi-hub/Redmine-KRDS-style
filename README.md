# Redmine KRDS Style

Redmine 6.1.6 + Vault(접속정보) 플러그인을 **KRDS(대한민국 정부 디자인 시스템) 스타일**과 한국어 운영 설정으로 묶은 Docker Compose 구성입니다.
공공 SI 프로젝트에 필요한 **요구사항 → 메뉴 → 일감 → 테스트 → 산출물** 흐름과 DB·배포·운영 관리를 플러그인으로 더했습니다.
데이터는 포함하지 않으며, 새 서버에서 아래 순서대로 설치하면 같은 화면·설정으로 시작합니다. 데스크톱과 모바일(반응형) 화면을 모두 지원합니다.

## 프로젝트 메뉴
모듈이 많아 **대분류 7개 + 하위 메뉴(2뎁스)** 로 묶었습니다. 대분류를 누르면 [KRDS 메인 메뉴](https://www.krds.go.kr/html/site/component/component_03_02.html)처럼 아래로 펼침 패널(아이콘·현재 메뉴 강조, 뒤 화면 어둡게)이 열리고, 모바일에서는 전체 화면 메뉴(왼쪽 대분류 탭 · 오른쪽 하위 메뉴)로 보입니다. 켜진 모듈만 보이며, 하위 메뉴가 없는 대분류는 숨깁니다.

| 대분류 | 하위 메뉴 | 플러그인 |
|---|---|---|
| 개요 | 개요 · 작업내역 | Redmine |
| 일감 | 일감 · 간트 차트 · 달력 · 로드맵 · 소요시간 | Redmine |
| 설계 | 요구사항 · 변경요청 · 메뉴 구조도 · 시스템 권한 · 용어사전 | qa_trace · pm_docs · menu_tree · glossary |
| 개발 | 저장소 · 프로그램 목록 · DB · 테스트 · 보안약점 · 배포 | Redmine · pm_docs · db_manage · qa_trace · jenkins_deploy |
| 운영 | 자산 · 스케줄러 · 점검·장애 · 인터페이스 · 접속정보 | ops_asset · Vault |
| 산출물 | 산출물 · 보고서 · 회의록 · 이슈·위험 · 감리 · 투입 인력 · 문서 · 파일 | pm_docs · Redmine |
| 협업 | 위키 · 게시판 · 뉴스 | Redmine |

- 프로젝트 설정 → 모듈은 같은 대분류 카드로 묶어 체크박스로 켜고 끕니다(카드별 모두 켜기·끄기, 켜진 개수).
- 대분류·아이콘 정의: `plugins/krds_ui/lib/krds_ui/menu_groups.rb` (새 플러그인 메뉴는 "기타"로)

## 주요 기능
| 영역 | 내용 |
|---|---|
| 메뉴 | 대분류 7개(개요·일감·설계·개발·운영·산출물·협업) + 2뎁스, KRDS 메인 메뉴형 펼침 패널(아이콘), 모바일 전체 화면 메뉴, 모듈 설정 대분류 카드 |
| 디자인 | KRDS 색상·간격 토큰, Pretendard GOV 글꼴, 반응형(모바일 카드형 목록·전체 화면 메뉴), 박스형 설정 탭, 관리 카드 메뉴, 하단 버튼 오른쪽 정렬(취소는 테두리 버튼), **알림·확인창은 KRDS 모달**(브라우저 기본 alert·confirm 대신) |
| 대시보드 · 보고서 | **프로젝트 현황(PMO)**: 전체 프로젝트 신호등·진척 대비 경과·지표 비교, 프로젝트 개요 위 종합 카드(요구사항·프로그램·테스트·위험·산출물·변경요청·일감·SR·감리), 주간·월간 보고서 미리보기·엑셀 |
| 유지관리 | 일감 유형 **SR**(요청 구분·긴급도·요청자), 긴급도로 처리 기한 자동(영업일), 기한 준수율(SLA) |
| 감리 · 인력 · 보안 | 감리 지적사항(시정조치 계획·결과), 투입 인력(계획·실적 M/M, 보안서약서·계정 회수, 교체 이력), 보안약점 진단(도구 결과 가져오기, 조치·예외, 재진단) |
| 백업 | 매일 DB·첨부파일·키 파일 서버 안 백업(날짜별 스냅숏, 14일), 복원 스크립트, 관리 → 백업 화면 |
| 일감 · 작업내역 | 검색조건 접기·적용 개수 표시, 더보기(…) 메뉴, 작업내역 오전/오후 12시간제, 사용자 시간대 서울 |
| 문서 | 게시판형 목록, 범주 배지·범주/제목 검색, 상세 화면, 편집할 때 첨부 추가·삭제 |
| 게시판 · 뉴스 · 파일 | 게시판 목록·글 목록·글 상세(상단 고정·잠금 배지, 답글, 취소 버튼), 뉴스·파일 제목 검색 |
| 접속정보 (Vault) | 한국어 화면, 검색·선택 삭제, 비밀번호 가림·복사, 관리자가 정하는 유형 목록(관리 → 접속정보(Vault) → 유형 관리) |
| Jenkins 배포 | 프로젝트 "배포" 탭에서 실행(Jenkins 매개변수 선택, 운영 배포 식별자 확인), 진행 중 스피너·진행바, 이력(커밋 수·리비전) |
| 용어사전 | 프로젝트 "용어사전" 탭(프로젝트 용어 + 전사 공통 용어), 관리 → 공통 용어사전, 용어·영문명·약어·분류 검색, CSV 가져오기·내보내기(엑셀 호환), 위키·일감 본문 `{{term(용어)}}` |
| DB 관리 | 관리 → DB 서버(개발/운영 구분, MariaDB·MySQL, PostgreSQL, MS SQL Server, Oracle, 비밀번호 암호화, SSH 터널, 저장 전 연결 시험), 프로젝트 "DB" 탭: 종류별 탭(테이블·뷰·함수·프로시저·트리거·DB 잡·시퀀스 — DB 종류마다 다름)·정의 SQL·숫자 요약, 테이블 정의서(엑셀), ERD(Mermaid — .md/.mmd/SVG/PNG), 개발/운영 비교(객체 포함), 용어사전 점검, 개인정보 컬럼(분류·암호화·경고), 위키·일감 본문 ```mermaid 그림 |
| 메뉴 구조도 | **사이트별 관리**(사용자·관리자 페이지 등), **화면 캡처**(서버가 로그인해 운영 화면 자동 캡처 → 화면 설계서), 엑셀형 표(뎁스 칸 자동·칸 바로 편집·Tab 들여쓰기·끌어서 옮기기), 추가 칼럼, 메뉴 ↔ 일감 여러 개 연결·메뉴별 일감 일괄 생성, 엑셀 가져오기·내보내기, 구조도(Mermaid)·현황, 일감 화면 메뉴 선택·일감 목록 메뉴 열/검색조건 |
| 시스템 권한 | 개발 대상 시스템의 권한 등급(예: 일반회원·운영자·관리자), 메뉴 × 권한 매트릭스(조회 R · 편집 CRU · 전체 CRUD), 엑셀 내보내기 |
| 요구사항 · 테스트 | 공공 표준 분류(SFR·PER·SIR…) 요구사항, 메뉴·일감 연결, **추적표**(요구사항 → 메뉴 → 일감 → 테스트)·위험 표시·변경 이력, 테스트 케이스·회차별 결과 입력, 불합격 → 결함 일감·재테스트 표시, 요구사항 정의서·추적표·테스트 시나리오·결과서 엑셀 |
| 역할 · 권한 | 역할 4종(PM/PL · 개발자 · 디자이너 · 조회자), 완료·거절은 PM/PL 만, 보류는 작업자도 선택, 프로젝트 비공개(구성원만 보임), 관리 → 역할 및 권한(역할 · 권한 설정 탭 — 영역별 요약 + 권한 체크·저장 한 화면) · 업무흐름 설정 · 항목 편집 권한 설정 |
| 운영 관리 | 인프라 **자산 대장**(만료 알림), **시스템 스케줄러**(cron 풀이·다음 실행·24시간 타임라인·crontab/DB 잡/Jenkins 가져오기), **점검·장애**(장애 기록·정기점검·월간 보고서), **연계 인터페이스**(정의서·구성도) |
| 산출물 관리 | 단계별 **산출물**(표준 34종·첨부 버전·자동 생성 23종·**검수용 일괄 zip**), **변경요청**(영향 분석·승인·반영 일감), **프로그램 목록**(메뉴에서 생성·소스 경로 추천), **회의록**(후속 조치 → 일감), **이슈·위험**(매트릭스) |
| 관리 도구 | 관리 → **메일 서버(SMTP)**: 화면에서 설정(비밀번호 암호화)·저장 전 시험 메일·저장 즉시 적용 / 관리 → **저장소 사용자 연결**: 커미터를 지금 사용자 로그인 ID·메일로 자동 연결, 사용자 생성·ID 변경 시 자동 연결 / 저장소 **소스코드 다운로드**(zip) |
| 운영 설정 | 역할 권한·업무흐름 기본값·일감 유형·상태·안내문 등 기준 설정을 `setup/seed.yml` 로 재현 |

## 구성
| 경로 | 내용 |
|---|---|
| `Dockerfile` | `redmine:6.1.6` 공식 이미지 + Vault 0.10.5 (커밋 고정) |

## 설치 (Rocky Linux 9 기준)
### 1. Docker 설치 (서버당 1회)
```bash
sudo dnf -y install dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo
sudo dnf -y install docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
sudo firewall-cmd --permanent --add-port=3000/tcp && sudo firewall-cmd --reload
```

### 2. 내려받기 · 비밀값 준비
```bash
git clone <저장소 주소> redmine && cd redmine
cp .env.example .env && chmod 600 .env
# .env 의 빈 값 채우기 — openssl rand -hex 32 (SYS_API_KEY 는 -hex 20)
```
> `.env` 는 Git 에 올라가지 않습니다. **`REDMINE_CIPHER_KEY` 를 잃으면 저장된 접속정보를 복구할 수 없으니** 안전한 곳에 따로 보관하세요.

### 3. 실행 · 기본 데이터 · 기준 설정
```bash
docker compose up -d --build
docker compose logs -f redmine          # "Listening on" 이 나오면 Ctrl+C
docker compose exec redmine sh -c 'bundle exec rake redmine:load_default_data REDMINE_LANG=ko'
docker compose exec redmine sh -c 'bundle exec rails runner setup/apply_settings.rb'
```
`apply_settings.rb` 는 테마·한국어·시간대(서울)·이름 표시(성이름)·첨부 1GB·커밋 키워드·역할 권한·안내문 등을 적용합니다. 시간대를 지정하지 않은 계정은 서울로 맞춥니다. 여러 번 실행해도 결과가 같습니다.

### 4. 커밋 자동 가져오기 (선택)
`setup/cron.example` 의 `KEY` 를 `.env` 의 `REDMINE_SYS_API_KEY` 로 바꿔 `/etc/cron.d/redmine_fetch` 로 저장하고 `chmod 600`.

### 5. 백업 cron (권장)
`setup/cron.example` 의 "PMS 백업" 3줄을 `/etc/cron.d/redmine_backup` 로 저장하고 `chmod 600` (매일 03:00 + 화면 [지금 백업] 요청 확인). 아래 "백업 · 복원" 참고

### 6. 화면 캡처 cron (선택)
`setup/cron.example` 의 "메뉴 구조도 화면 캡처" 줄을 `/etc/cron.d/redmine_capture` 로 저장하고 `chmod 600` (캡처 설정의 자동 캡처가 켜진 사이트만 새벽 4시)

### 7. 접속
`http://<서버IP>:3000` — 초기 계정 **admin / admin** (로그인 후 즉시 변경)

## 수정 · 배포
수정 → 커밋 → push 후 서버에서 **`cd /root/redmine && ./deploy.sh`** 한 줄이면 됩니다. 바뀐 파일을 보고 알아서 처리합니다.

| 바꾸는 것 | deploy.sh 가 하는 일 |
|---|---|
| 테마 CSS·JS, 플러그인 화면, 번역 | Redmine 재시작 |
| 플러그인 DB 변경 (`plugins/*/db/migrate`) | 재시작 때 자동 반영 (`REDMINE_PLUGINS_MIGRATE`) |
| 기준 설정 (`setup/seed.yml` · `welcome.md`) | 재시작 + `apply_settings.rb` 실행 |
| Redmine / Vault 버전 (`Dockerfile`, `compose.yaml`), 플러그인 Gemfile(`db_manage`·`menu_tree`) | 이미지 다시 빌드 (브랜치에서 먼저 시험 권장) |

> **관리 화면에서 바꾼 기준 설정은 `setup/seed.yml` 에도 반영하세요.** 역할 권한·일감 유형·사이트 제목 등을 화면에서만 바꾸면, 다음에 `seed.yml`·`welcome.md` 가 바뀌는 배포 때 `apply_settings.rb` 가 다시 적용되면서 원래 값으로 돌아갑니다.

서버는 GitHub 저장소의 읽기 전용 Deploy key 로 받아옵니다 (`~/.ssh/config` 의 `Host github-redmine`).
서버에서 파일을 직접 고치지 마세요 — 다음 배포 때 `git pull` 이 멈춥니다.

- Vault 화면은 이미지 빌드 중 `plugins/vault_ko/build.rb` 가 원본 화면을 고쳐 만듭니다. Vault 버전을 올렸을 때 원본 문구가 바뀌어 맞지 않으면 `[못 찾음]` 을 출력하고 빌드가 멈춥니다.
- 글꼴(Pretendard GOV)은 공식 배포본을 jsDelivr CDN 으로 불러옵니다. 인터넷이 안 되는 서버에서는 시스템 글꼴(맑은 고딕 등)로 보입니다.
- **알림·확인창**: `theme.js` 의 `KrdsDialog.alert(메시지)` / `KrdsDialog.confirm(메시지)`(Promise) — KRDS 모달 규격. `window.alert` 와 rails-ujs `data-confirm`(`Rails.confirm`)을 바꿔 두어 Redmine·플러그인의 기존 알림·확인도 모달로 뜹니다. 새 화면 코드에서는 `confirm()` 대신 `KrdsDialog.confirm(...).then(ok => …)` 를 쓰세요(모달은 기다리지 않으므로 알림 뒤 새로 고침은 `.then` 안에서).
- 반응형: 모바일 퍼스트 — 기본 규칙은 모바일 기준, 데스크톱 전용 배치는 `application.css` 끝의 `@media (min-width:900px)` 에 둡니다. Redmine 의 `responsive.css` 가 테마보다 뒤에 로드되므로 모바일에서 덮어쓸 규칙에는 `#wrapper` 를 붙여 우선순위를 높입니다.
- CSS 작성 규칙: 규칙은 한 줄, 클래스명은 언더바(`_`)로 최대 2단어, 속성 순서는 display → position → flex → 크기 → 여백 → 테두리 → 배경 → 글꼴 → 색. Redmine 기본 선택자(`#main-menu` 등)는 예외입니다.

## 설계 — 메뉴 구조도 · 시스템 권한
1. **프로젝트 → 설정 → 모듈**에서 "메뉴 구조도"(필요하면 "시스템 권한"도) 켜기
2. **프로젝트 → 메뉴 구조도 → 표**: [1뎁스 메뉴 추가] 또는 [가져오기]로 엑셀(xlsx·CSV)을 올림
   - 뎁스 칸(1뎁스·2뎁스… / 대메뉴·중메뉴·소메뉴 / Level 1…)은 가장 깊은 메뉴에 맞춰 자동으로 늘어남. 윗 뎁스 칸이 비어 있으면 윗줄 값을 이어받음(셀 병합 가능)
   - 칸을 누르면 바로 고침: Enter 저장 후 아래로, Tab 다음 칸, Esc 취소 / 메뉴명 칸에서 Tab 들여쓰기 · Shift+Tab 내어쓰기 / ⋮⋮ 를 끌어 옮기기 / 행 ⋯ 메뉴(아래·하위 추가, 위·아래, 일감, 삭제)
   - 기본 칼럼: 화면 ID · URL · 화면 유형(목록·상세·등록·수정·팝업·탭·링크) · 채널(공통·PC·모바일) · 대상 권한(시스템 권한 매트릭스) · 사용 · 일감 · 진행률 · 비고, [칼럼 관리]로 텍스트·선택 목록·체크·날짜 칼럼 추가
   - 메뉴를 골라 [고른 메뉴로 일감 만들기] — 일감 유형·제목 형식(`[화면 ID] 메뉴 경로` 등)·담당자·상위 일감·기간, 이미 일감이 있는 메뉴 건너뛰기
   - [엑셀 내보내기] 파일을 고쳐 다시 가져오면 같은 경로의 메뉴는 값만 갱신
3. **일감**: 등록·편집 화면 "메뉴" 칸에서 메뉴를 찾아 여러 개 연결, 상세에 연결된 메뉴, 일감 목록에 "메뉴" 열·검색조건(상위 메뉴를 고르면 하위 메뉴 일감까지)
4. **구조도**: Mermaid 그림(완료·진행·일감 없음·미사용 색 구분), 1뎁스·표시 뎁스·가로/세로, `.md` · `.mmd` · SVG · PNG 내려받기 / **현황**: 화면(말단 메뉴) 기준 일감 연결·완료·진행률, 1뎁스별·화면 유형별, 일감이 없는 화면 목록
5. **시스템 권한**: 권한 등급(등급 숫자·코드·설명·**적용 사이트** — 비우면 모든 사이트) → **메뉴 권한 매트릭스**에서 칸을 눌러 없음 → R → CRU → CRUD, 열 [모두 조회], 메뉴 ↓ 로 하위 메뉴에 같은 값 적용, 사이트 선택(전체 사이트는 사이트별 묶음, 다른 사이트 전용 등급은 `·`), 엑셀(메뉴 권한 · 권한 등급 · 표기 시트)
6. **사이트** (사용자 페이지 · 관리자 페이지처럼 한 프로젝트에 여러 시스템): 표 위 [사이트 나누기]/[사이트 관리]에서 이름·코드·기본 주소·순서 지정 → 표·구조도·현황·시스템 권한 위 **사이트 선택**
   - 처음 만든 사이트가 기존 메뉴를 모두 가져감, 하위 메뉴는 1뎁스 메뉴의 사이트를 따름, 행 ⋯ 메뉴 [○○(으)로 옮기기]로 다른 사이트로 이동(하위 포함)
   - 엑셀 첫 칸 **사이트**(가져오기: 없는 사이트는 새로 만듦, 빈칸은 윗줄 사이트, 사이트 칸이 없으면 고른 사이트로 — 전체 바꾸기도 그 사이트만)
   - 사이트가 둘 이상이면 메뉴 경로·선택 목록에 `[관리자 페이지] 회원 관리 > 목록` 처럼 표시(일감·요구사항·변경요청·테스트·프로그램·산출물 엑셀). 메뉴가 남아 있는 사이트는 지울 수 없음
7. **메뉴 노출** (Y/N): 실제 사이트 메뉴에 보이면 Y, 메뉴에는 없고 화면만 있으면 N(상세·등록·수정·팝업·탭은 기본 N, 바꿀 수 있음). 표·엑셀 칸, 구조도 **[메뉴만 보기]**(사이트맵·메뉴판), 화면만 있는 항목은 둥근 사각형. 현황·KPI 의 "화면" = 화면 유형·화면 ID 가 있거나 말단인 항목 — 작성 규칙은 초기화면 안내문(`setup/welcome.md`) 참고
8. **화면 캡처** (메뉴 구조도 › 화면 캡처 탭): 서버의 헤드리스 크롬이 운영 사이트에 로그인해 메뉴 구조도의 화면 URL 을 차례로 열고 캡처 → 화면 설계서
   - **캡처 설정**(사이트별, 권한 "화면 캡처 설정·실행" — PM/PL): 기본 주소, 로그인 주소·아이디·비밀번호(`REDMINE_CIPHER_KEY` 로 암호화, 다시 표시 안 함), **로그아웃 주소**(로그인 후 화면에 그 주소로 가는 링크·폼·onclick 이동이 있으면 로그인 성공 — 버튼이 아닌 글자 링크·스크립트 이동도 인정), 입력칸·로그인 버튼·로그인 확인 선택자(비우면 userId·username·loginId·password·submit 등 흔한 이름으로 찾음, 로그아웃 주소가 없을 때는 확인 요소 → 비밀번호 칸이 사라졌는지로 판단), 너비(기본 1440)·모바일(390px)도·기다림·최대 높이·보관 횟수·자동 캡처(매일·매주 월), **[로그인 시험]**(로그인 결과 화면을 보여 줌)
   - **[지금 캡처]**: 백그라운드로 실행(화면이 5초마다 진행 표시), 메뉴 URL 이 `/`로 시작하면 기본 주소의 호스트 뒤, 상대 주소는 기본 주소 뒤에 붙임, 세션이 끊기면 다시 로그인, HTTP 400 이상은 오류, 직전과 다르면 "바뀜", 화면별 최근 N 회만 보관
   - 화면 카드(최신 미리보기·바뀜·오류·캡처 없음·URL 없음), 화면별 이력·두 시점 나란히 비교·원본·모바일·내려받기
   - 파일은 `files/menu_captures/` (PMS 백업에 포함). 자동 캡처는 cron `rake redmine:menu_tree:capture` (`setup/cron.example`)
   - **화면 설계서(PPT)** — 화면 캡처 탭 [화면 설계서(PPT)] 또는 산출물 **D-03 화면 설계서** [최신본 받기]: 16:9 PowerPoint, 표지(대표 화면) · 개정 이력 · 화면 목록(쪽 번호) · **화면마다 1장**(캡처 + 화면 ID·화면명·메뉴 경로·URL·화면 유형·메뉴 노출·접근 권한·요구사항·프로그램(처리 구분)·캡처 일시 + 화면 설명 빈칸), 세로로 긴 화면은 최대 3장으로 나눔, 모바일 캡처는 모바일 장. 사이트가 여럿이면 사이트별 파일. 글꼴 맑은 고딕 (`KrdsUi::Pptx` — 추가 gem 없이 생성)
   - 캡처 원본이 필요하면 자동 생성 "화면 캡처 원본 (PNG + 화면 목록)" 을 고름
   - PMS 서버에서 대상 사이트로 접속할 수 있어야 합니다. 캡처에는 화면 내용이 그대로 담기므로 **조회 권한만 있는 테스트 계정·테스트 데이터**로 캡처하세요
   - 이미지에 chromium · fonts-noto-cjk 가 들어가 이미지가 약 2.4GB 입니다 (gem `ferrum` 은 `plugins/menu_tree/Gemfile`)

## 설계 — 요구사항 · 개발 — 테스트
`plugins/qa_trace` — 프로젝트 설정 > 모듈에서 **요구사항**, **테스트**를 켭니다. 메뉴 연결은 "메뉴 구조도" 모듈도 켜야 합니다.
1. **요구사항**: ID 는 공공 표준 분류 접두어(SFR 기능 · PER 성능 · SIR 인터페이스 · DAR 데이터 · TER 테스트 · SER 보안 · QUR 품질 · COR 제약 · PMR 관리 · PSR 지원) + 번호, 비우면 자동(SFR-001)
   - 상세 내용·출처·중요도(상/중/하)·상태(접수/확정/변경/삭제)·상위 요구사항, 메뉴 여러 개(하위 메뉴 포함)·일감 번호 연결
   - 목록 KPI: 전체·확정·메뉴 미연결·테스트 없음·불합격 있음·테스트 통과(누르면 걸러 봄), 삭제됐는데 일감이 진행 중이면 따로 표시
   - **추적표**: 요구사항 | 메뉴 | 일감(완료 줄긋기) | 테스트 케이스와 최근 결과 | 위험
   - 상세: 연결 일감·테스트 케이스, 하위 요구사항, **변경 이력**(칸별 이전 → 이후, 메뉴·일감 연결 변경 포함)
   - 엑셀: 요구사항 정의서 · 추적표 · 분류 시트로 내보내기 / 가져오기는 머리줄 이름으로 칸을 찾음(요구사항 ID·분류·요구사항명·상세·출처·중요도·상태·상위 ID·메뉴), ID 가 같으면 값만 갱신, ID 가 없으면 같은 분류·이름으로 찾고 없으면 새로 만듦
2. **테스트**: 케이스(단위·통합·인수, 메뉴 하나·요구사항 여러 개, 사전조건·절차·기대결과), 메뉴별 현황(케이스 없는 화면 확인)
   - 케이스에 **프로그램**(프로그램 목록의 기능) 연결 — 단위테스트는 프로그램 ID 기준, 메뉴를 비우면 프로그램의 화면, 시나리오·결과서에 프로그램 ID
   - **회차**(예: 1차 통합테스트): 만들 때 종류가 맞는 사용 중 케이스가 대상, 나중에 추가된 케이스는 [새 케이스 대상에 추가]
   - 결과 입력: 한 화면에서 결과(미수행·합격·불합격·보류·제외)·비고를 고치고 한 번에 저장(바뀐 줄 표시)
   - 불합격 줄 [결함 일감 만들기] → "결함" 트래커 일감(절차·기대결과·실제 결과 자동 기록, 메뉴 연결), 결함 일감이 완료되면 **재테스트** 표시
   - 엑셀: 테스트 시나리오 내보내기·가져오기, 회차별 테스트 결과서(결과 요약 · 테스트 결과 시트)
3. **일감 상세**: 연결된 요구사항, 테스트 결함이면 어느 회차·케이스에서 나왔는지
- 권한: 보기 모든 역할, 요구사항 편집 PM/PL, 테스트 결과 입력 PM/PL·개발자·디자이너, 케이스·회차 편집 PM/PL·개발자 (`setup/seed.yml`). DB 테이블은 컨테이너 시작 때 자동 생성됩니다.

## 설계 — 용어사전
1. **프로젝트 → 설정 → 모듈**에서 "용어사전" 켜기 → 프로젝트 메뉴에 **용어사전** 탭이 생깁니다.
2. 모든 프로젝트가 함께 쓰는 용어는 **관리 → 공통 용어사전**에 등록합니다(관리자만). 프로젝트 화면에는 `공통` 배지로 함께 보입니다.
3. 엑셀로 정리한 용어는 [가져오기]로 올립니다. 머리줄 `용어,영문명,약어,분류,데이터타입,길이,정의,비고` (용어만 필수, 'CSV UTF-8'·'CSV(쉼표로 분리)' 모두 가능). [내보내기] 파일을 고쳐서 다시 올려도 됩니다.
   - **행정안전부 공공데이터 공통표준용어 CSV**(공공데이터포털 배포 파일)는 그대로 올리면 됩니다 — 도메인(예: `명V100`)은 분류·데이터 타입·길이로, 허용값·저장/표현 형식·행정표준코드·이음동의어·제정차수는 비고로, 폐기된 용어는 제외. 새 차수가 나오면 "덮어쓰기"를 체크해 다시 올리면 갱신됩니다(1만 3천 건 약 30초)
4. 위키·일감 본문에 `{{term(고객번호)}}` 라고 쓰면 `고객번호 (CUST_NO)` 로 표시되고 정의가 툴팁으로 나옵니다. 같은 이름이 있으면 프로젝트 용어가 우선입니다.
- 권한: 보기는 모든 역할, 등록·수정·삭제·가져오기는 PM/PL·개발자 (`setup/seed.yml`). DB 테이블은 컨테이너 시작 때 자동 생성됩니다.

## 개발 — DB 관리
1. **관리 → DB 서버**: 구분(개발/운영)·DB 종류·호스트·포트·DB 이름·계정·비밀번호를 입력하고 폼의 [연결 시험]으로 저장 전에 접속 확인(편집 중 비밀번호를 비워 두면 저장된 비밀번호 사용), 목록에서도 [연결 시험] (비밀번호는 `REDMINE_CIPHER_KEY` 로 암호화 저장, 화면에 다시 표시하지 않음). **SELECT 권한만 있는 조회 전용 계정**을 권장합니다.
2. **프로젝트 → 설정 → 모듈**에서 "DB 관리" 켜기 → **설정 → DB** 탭에서 개발DB·운영DB 등을 추가 (서버 선택 — 운영/개발 표시는 DB 서버 구분을 따름, 스키마 — 비워 두면 MariaDB 는 서버의 DB 이름, PostgreSQL 은 `public`)
3. **프로젝트 → DB** 탭: DB 별로 종류 탭을 눌러 조회, 아래에 종류별 개수·전체 컬럼·추정 행 합계·용어 일치율
   | DB | 종류 탭 |
   |---|---|
   | MariaDB | 테이블 · 뷰 · 함수 · 프로시저 · 트리거 · DB 잡(이벤트) · 시퀀스 |
   | MySQL 8 | 테이블 · 뷰 · 함수 · 프로시저 · 트리거 · DB 잡(이벤트) |
   | PostgreSQL | 테이블 · 뷰 · 구체화 뷰 · 함수 · 프로시저 · 트리거 · 시퀀스 (+ DB 잡: pg_cron 이 있을 때) |
   | MS SQL Server | 테이블 · 뷰 · 함수 · 프로시저 · 트리거 · 시퀀스 · 시노님 · DB 잡(SQL Server 에이전트 작업) |
   | Oracle | 테이블 · 뷰 · 구체화 뷰 · 함수 · 프로시저 · 패키지 · 트리거 · 시퀀스 · 시노님 · DB 잡(스케줄러 작업) |
   - 테이블: 컬럼·타입·NULL·기본값·PK/UK/FK/IX·설명·용어사전 대조, **인덱스**(이름·구분·컬럼 순서·방식), 걸린 트리거
   - 읽은 정보는 10분 동안 보관(화면마다 DB 에 새로 접속하지 않음), [새로 고침]으로 바로 다시 읽기 / 뷰: 컬럼과 정의 SQL / 함수·프로시저·트리거·DB 잡·시퀀스: 속성과 정의 SQL
   - 조회 전용 계정에 안 보이는 객체가 있으면 탭에 필요한 권한을 안내합니다. MariaDB 는 `GRANT SELECT ON mysql.proc`(함수·프로시저)·`GRANT SELECT ON mysql.event`(DB 잡), MySQL 8 은 `GRANT SHOW_ROUTINE ON *.*` — 모두 읽기 전용. 트리거는 MariaDB·MySQL 모두 TRIGGER 권한(쓰기 포함)이 있어야 보입니다. PostgreSQL 은 조회 전용 계정으로 모두 보입니다. SQL Server 는 정의를 보려면 `GRANT VIEW DEFINITION`, 에이전트 작업은 msdb 의 `SQLAgentReaderRole`. Oracle 은 DB 이름 칸에 서비스 이름, 다른 스키마의 소스는 EXECUTE 권한 또는 `SELECT_CATALOG_ROLE`.
   - **ERD**: Mermaid 로 그린 ERD(실선 FK 제약, 점선 추정 관계 — FK 없이 다른 테이블 PK 와 이름이 같은 컬럼), 테이블 선택·컬럼 표시(전체/키/테이블명)·확대·축소. 내려받기 `.md`(깃허브·VS Code·Redmine 위키에서 그림으로 보임) · `.mmd`(Mermaid 원문) · **draw.io**(위치·선을 직접 고치는 파일) · SVG · PNG. 뷰는 제외, 영문이 아닌 컬럼 이름은 `col_순번`(설명에 원래 이름)
   - **테이블 정의서**: 엑셀(xlsx) 시트 — 테이블 목록 / 컬럼 정의 / 인덱스 / 뷰·함수·트리거·잡
   - **비교**: 두 DB 의 한쪽에만 있는 테이블, 컬럼 차이(타입·NULL·기본값·설명·키), 뷰·함수·프로시저·트리거·DB 잡·시퀀스의 있음/없음·정의 차이
   - **변경 이력**: [지금 구조 저장] 또는 cron 자동 저장(`rake redmine:db_manage:snapshot`, setup/cron.example) — 구조가 바뀌었을 때만 저장(연결마다 최근 100개), 앞 저장본과의 차이 요약(테이블 추가·삭제·변경, 객체 변경), 저장본끼리·지금 DB 와 비교
   - **SQL 조회**: (SQL Server 는 읽기 전용 트랜잭션이 없어 트랜잭션 안에서 실행 후 항상 되돌림) 조회 문장 하나만(SELECT·WITH·SHOW·DESC·EXPLAIN SELECT), 변경·여러 문장·INTO·FOR UPDATE 거부, DB 쪽 읽기 전용 트랜잭션·실행 시간 제한(응답 대기 × 3, 최대 60초)·건수 제한(100/500/1000), CSV 받기, 실행 기록(거부·오류 포함). 권한은 `SQL 조회 (개발 DB)` / `SQL 조회 (운영 DB)` 따로 — 운영 DB 권한은 기본으로 아무 역할에도 없음
   - **용어 점검**: 컬럼명을 용어사전 약어와 대조(일치·타입 다름·미등록, 미등록 컬럼 CSV), 설명(코멘트) 누락 테이블·컬럼, 설명이 용어 이름과 다른 컬럼
- **SSH 터널** (DB 에 바로 접속할 수 없을 때, 예: Redmine → WEB 서버 → 운영 DB): DB 서버 편집에서 "SSH 터널 사용" → SSH 서버·포트·계정, 비밀번호 또는 개인키(OpenSSH·PEM, ed25519·RSA·ECDSA, 키 암호 선택). DB 호스트는 **SSH 서버에서 본 주소**로 적습니다.
  - 조회하는 동안만 터널을 열고 바로 닫습니다. 비밀번호·개인키는 암호화 저장, 화면에 다시 표시하지 않습니다.
  - SSH 서버 지문(SHA256)을 첫 연결 때 기록하고 이후 다르면 거부합니다(서버 교체 시 편집 화면에서 지문 초기화).
  - 여러 서버를 거쳐야 하면 [경유 서버 추가]로 최대 3대까지 (예: Redmine → WEB → WAS → DB). 경유 서버마다 계정·비밀번호/개인키·지문을 따로 관리하고, DB 호스트는 마지막 서버에서 본 주소로 적습니다.
  - SSH 서버에서 포트 전달이 허용되어야 합니다(`AllowTcpForwarding`). 쉘을 막고 포트 전달만 허용한 전용 계정을 권장합니다(예: `authorized_keys` 에 `restrict,port-forwarding,permitopen="DB주소:3306"`).
- 위키·일감·문서 본문의 ` ```mermaid ` 블록은 그림으로 보입니다 (Mermaid 11.4.1 을 플러그인에 포함 — 인터넷 연결 불필요, MIT 라이선스).
- 원격 DB 에는 읽기 전용 세션으로 접속해 테이블·컬럼 정보(메타데이터)만 읽습니다. 데이터 조회·변경 SQL 은 실행하지 않습니다.
- **개인정보 컬럼** (프로젝트 → DB → [개인정보]): 컬럼마다 분류(고유식별정보·비밀번호·바이오정보·계좌·카드·민감정보·일반 개인정보·개인정보 아님)와 암호화(양방향·단방향·미적용·미확인)를 기록. 컬럼 이름·설명·용어사전으로 **자동 후보**를 찾고 사람이 확정한 것만 저장, **경고**(암호화 필수인데 미적용, 비밀번호가 단방향 아님, 미확인, 표시한 컬럼이 DB 에서 사라짐), 테이블 상세에 배지, 엑셀(개인정보 컬럼 · 분류별 요약). 보기는 DB 보기 권한, 확정·수정은 DB 연결 관리 권한
- 권한: 보기 PM/PL·개발자, SQL 조회(개발 DB) PM/PL·개발자, DB 연결 관리(+이력 저장·SQL 실행 기록 보기) PM/PL (`setup/seed.yml`). Redmine 컨테이너에서 DB 서버 주소·포트로 접속할 수 있어야 합니다.

## 개발 — Jenkins 배포 연동
Jenkins 쪽은 플러그인 설치 없이 **배포 전용 계정 + API 토큰**만 준비합니다 (배포 작업의 Read·Build 권한만 권장).

1. **관리 → Jenkins 서버**: 주소·계정·API 토큰 등록 후 [연결 시험] (토큰은 `REDMINE_CIPHER_KEY` 로 암호화 저장, 화면에 다시 표시하지 않음)
2. **관리 → 역할 및 권한**: "배포" 항목의 권한 지정 — 배포 이력 보기 / 배포 실행 / 운영 배포 실행 / 배포 설정 관리
3. **프로젝트 → 설정 → 모듈**에서 "배포" 켜기 → **설정 → 배포** 탭에서 환경(개발서버·운영서버 등)별 Jenkins 작업 경로·기본 매개변수(확인창 초기값, 예: `DEPLOY_PROD=true`) 지정
4. **프로젝트 → 배포** 탭에서 [배포 실행] — 확인창에서 Jenkins 작업의 매개변수를 체크박스·선택 목록·입력칸으로 선택, 운영 환경은 프로젝트 식별자를 입력해야 실행. 진행 중에는 스피너와 진행바(Jenkins 예상 소요 시간 기준)를 보여 주고 끝나면 자동 갱신

- Jenkins 에 정의된 매개변수만 전달하고(비밀번호 매개변수는 표시·전달하지 않음), 선택 목록은 Jenkins 선택지만 허용합니다.
- `REDMINE_USER`·`REDMINE_RUN_ID` 를 정의해 두면 실행자와 기록 번호를 자동으로 받습니다. 초기화면 안내문에 단계별 연결 가이드가 있습니다.
- 배포 이력의 **변경 내역** 칸은 Jenkins 빌드에 포함된 커밋 수·최신 리비전·메시지를 보여 줍니다(전체 보기로 목록 펼침, 리비전은 Redmine 저장소 화면으로 연결). 변경이 없는 빌드는 그 시점 Redmine 저장소의 최신 리비전을 보여 줍니다.
- Redmine 서버(Docker 컨테이너)에서 Jenkins 주소로 접속할 수 있어야 합니다. DB 테이블은 컨테이너 시작 때 자동 생성됩니다.

## 백업 · 복원
Git 에는 데이터가 없으므로 서버에서 매일 백업합니다 (`setup/backup.sh`, cron `/etc/cron.d/redmine_backup` — `setup/cron.example`).
- **대상**: DB(`pg_dump -Fc`, db 컨테이너에서), 첨부파일(`files` 볼륨), 접속정보 키 파일(`keys` 볼륨)
- **위치**: `backup/db/db_<YYYY-MM-DD_HHMM>.dump`, `backup/files/<YYYY-MM-DD_HHMM>/{files,keys}` — 첨부는 `rsync --link-dest` 스냅숏이라 바뀌지 않은 파일은 하드링크(용량이 늘지 않음)
- **보관**: `.env` 의 `BACKUP_KEEP_DAYS`(기본 14일), 가장 최근 것은 항상 남김. 동시에 하나만, 같은 분에 두 번이면 다음 분까지 기다림
- **관리 → 백업**: 목록·결과·용량·디스크 여유, 26시간 넘게 성공이 없으면 경고, [지금 백업](요청을 남기면 1분 안에 cron 이 실행). 컨테이너에는 상태 폴더 `backup/ctl` 만 마운트
- **복원**: `setup/restore.sh` (목록) → `setup/restore.sh <이름> [--db|--files]` — RESTORE 입력 확인 → 지금 상태 한 번 더 백업 → Redmine 멈춤 → `pg_restore --clean` → 첨부·키 되돌림 → 시작
- **`.env` 는 백업에 넣지 않습니다**(`REDMINE_CIPHER_KEY` 가 없으면 접속정보·비밀번호를 풀 수 없음). 서버가 통째로 없어질 때를 대비해 `backup/` 과 `.env` 를 각각 서버 밖에 따로 보관하세요
- 새 서버로 옮길 때: 설치 1~3단계(같은 `.env`) → `backup/` 복사 → `setup/restore.sh <이름>`
